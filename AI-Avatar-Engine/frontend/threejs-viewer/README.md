# Avatar Sandbox

Developer tool for the AI-Avatar-Engine: inspect templates, drive
blendshapes and identity params, equip wardrobe assets, and run the full
**photos → avatar** AI pipeline — all in the browser.

## Run

Easiest — the repo's one-command launcher starts this AND the AI analyzer
server together (`AI-Avatar-Engine\run.cmd`). Manually:

```bash
npm install
npm run dev        # http://localhost:5173
```

The **Photos** tab additionally needs the analyzer server:
`ai\.venv\Scripts\python ai\photo_analyzer\server.py` (→ 127.0.0.1:8100).

## Tabs

| Tab | What it does |
|---|---|
| **Inspector** | Meshes (verts / morph counts / materials), material list with texture maps, full bone hierarchy |
| **Photos** | The AI pipeline end-to-end: drop a front photo (left/right optional), **Generate Avatar** → detected gender switches the base avatar, identity params apply, appearance labels auto-equip wardrobe. Tick **Debug** for the Photo Debug panel: aligned photos, landmark overlay, segmentation (hairline/beard), profile silhouettes, MICA 3D landmarks, every measurement with confidence + down-weights, and each parameter's provenance |
| **Blendshapes** | One slider per morph target, grouped by category (visemes, brow, eye, mouth, ...), searchable. Same-named targets across meshes are driven together — this mirrors the engine's runtime sync contract |
| **Identity** | The 20 semantic user params (0–1, 0.5 neutral) with per-category sliders **and** a live JSON editor. Uses `public/morph_definitions.json` — the same file as the Blender pipeline; the math is identical to `morph_controller.py` |
| **Appearance / Clothing / Accessories** | Wardrobe: equip/remove items (hair, beards, glasses, tops, ...) via `WardrobeManager`. Fully catalog-driven — each slot in `public/wardrobe/catalog.json` declares which of the three tabs it appears on, and colorable items get palette swatches; there is no per-category code |
| **Display** | Toggles: skeleton overlay, wireframe, vertex normals, UV checker, grid |
| **Export** | Download current scene as GLB (Three.js re-export) or the identity params JSON (the format `export_avatar_glb.py --params` accepts) |

## Avatars

`public/avatars/sandbox_male.glb` / `sandbox_female.glb` are **dev builds**
exported with `export_avatar_glb.py --keep-identity`: identity morphs stay
live (negative weights allowed) so the Identity tab works. Production avatars
bake identity instead.

Regenerate after template changes:

```bash
blender --background --python ../../blender/scripts/export_avatar_glb.py -- \
  ../../blender/templates/male_base.blend public/avatars/sandbox_male.glb --keep-identity
```

## Wardrobe assets

The asset system is documented in [docs/asset_system.md](../../docs/asset_system.md).
Short version: every item lives at
`public/wardrobe/<category>/<id>/{<id>.glb, item.json, thumbnail.png}` and is
registered in `public/wardrobe/catalog.json`; the canonical copies live in
`assets/shared/` and are (re)generated by `blender/scripts/build_demo_assets.py`
/ `build_hair_style.py` / `import_hair_pack.py` — don't hand-edit the sandbox
copies. Two attach types only: `bone` (rigid, authored bone-relative — meters,
glTF Y-up, avatar faces +Z) and `skinned` (re-bound to the avatar's bones by
name at equip time).

## Debugging

`window.sandbox` exposes `{ viewer, wardrobe, params, defs }` in the browser
console.
